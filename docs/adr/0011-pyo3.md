# 0011. Pin PyO3 0.29, free-threaded CPython from 3.14t, no 3.13t

## Context

User decision of 2026-10-02 (decision D-24, run spec revision 8). `pyo3-ffi` 0.29's `build.rs` sets
`MIN_FREE_THREADED_VERSION = 3.14` (verified), so PyO3 0.29 cannot build for CPython 3.13t. Staying on 0.28.3 would
carry RUSTSEC-2026-0176 (list/tuple iterator `nth`/`nth_back` out-of-bounds read) and RUSTSEC-2026-0177
(`PyCFunction::new_closure` missing `Sync`), both fixed only in 0.29. The user chose no advisory exceptions.

## Decision

Pin `pyo3 = "=0.29.x"` (the current 0.29 patch release, bumped only by a deliberate commit). The module declares
`gil_used = false`; every native method whose work is not constant runs inside `py.detach`; `panic = "unwind"` in
all profiles. Free-threaded CPython is supported from **3.14t**; 3.13t is not supported in this run. The CI matrix is
3.11, 3.13, 3.14 and 3.14t on Linux plus 3.13 on macOS.

## Alternatives considered

**Stay on PyO3 0.28.3** to keep 3.13t: needs two advisory exceptions in `deny.toml`, which the user declined.

## Consequences

This is a deliberate narrowing of design-spec C3 ("3.13t and later"). GIL builds 3.11-3.14 are unaffected. Revisit
3.13t only if a consumer needs it, which would require a PyO3 that supports it without the two advisories.
