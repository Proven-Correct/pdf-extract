# Architecture

pdf-extract is a pure-Rust PDF text extractor on a **patched, vendored fork of
five hayro crates**, with a PyO3 binding; its output must match PyMuPDF's
`get_text("text")` shape, and it must be safe on hostile input from many
threads. Pages without a text layer are rendered (hayro) and recognised with a
vendored Tesseract (run 0002). Everything below serves those constraints.
The current behavioural contract is `openspec/specs/<capability>/spec.md`
(13 capabilities, ADR 84). Each scenario there cites the row that decided it.
Authoritative detail and run history: `docs/specs/0001-text-path.md` (cited
"spec §n"), `docs/specs/0002-ocr.md` (cited "0002 §n", decisions "D-n"),
`docs/specs/0003-ocr-followons.md`, `docs/design-spec.md`, and one record per
decision in `docs/adr/` (cited "ADR n"). Why it is built this way:
`THEORY.md`. Build, test, usage: `README.md`. Update this file in the commit
that changes anything it states.

## Flow

`open` → `source::read_file` (size/kind checks, detection) → hayro `Pdf::new`
(lazy pages, H1) → `index` walk → `Document` (`Arc<DocShared>`). `Page::text` →
clone `Arc<Loaded>` → rebuild the hayro `Page` from its `PageRef` → hayro
`interpret_page` with a fresh `InterpreterCache`, budget and `TextDevice` →
`CharRecord`s + markers → `LineAssembler` → `TextPage` → serialised string.
Warnings come from `WarningSink`, fed by hayro's counters. Python calls the same
path inside `py.detach`, wrapped in `guard::guarded`.

**OCR flow.** `Document::extract` (or `Page::ocr`) → per page, text path first;
a page is *sparse* when its Unicode-trimmed code-point count is below
`min_chars` (50) → `Page::with_hayro_page` → `pdf_extract_render::render_gray`
(gray pixmap at `dpi`, clamped; budget and `max_image_pixels` enforced inside
hayro) → `OcrEngine` takes an instance from the pool → `OcrBackend::recognize`:
`TesseractBackend` in process (`Instance` over the C++ shim), or the
`isolation::client` writing a length-prefixed frame to a `pdf-extract-ocr-helper`
child over its stdin/stdout, with `poll(2)` deadlines → `TextPageBuilder` (drops empty words and words made only of space-like code points, the ADR 48 set) →
`TextPage` with `source = Ocr`. OCR candidates are chosen in page order so
results are deterministic under `workers > 1` (D-15); the document-level
`OcrStatus` precedence is Unavailable > BudgetExhausted > Partial > Ok. Language
data is found by O9 (`OcrConfig.tessdata`, `TESSDATA_PREFIX`, known distribution
directories, incl. `/opt/local/share/tessdata`; D-3); the library bundles none.

**Process isolation.** `Isolation::Process` (opt-in from Rust, where the default is `InProcess`; the Python default since internal #53, ADR 0092; D-6,
D-7) contains `abort()`/`ASSERT_HOST` in Tesseract: the helper dies, the page
fails, the slot respawns. The helper is found at an absolute
`PDF_EXTRACT_OCR_HELPER`, else beside the extension module, else beside the
executable; `PATH` is never searched (D-16). Measured overhead on clean 300 dpi
pages: 1.6 %. It contains crashes, not malice (no sandbox). `max_render_pixels` above `MAX_PROCESS_RENDER_PIXELS` (66,977,776, what one helper frame holds) is refused at construction under `Process` (Python `ValueError`), so the two modes never differ by raster size (O26). A `fork()` child
abandons the parent's pool (O30).

## Invariants

- **Never hold the `DocShared.state` lock across parsing or interpretation, and never store a hayro `Page` or `InterpreterCache`.** An operation clones the `Arc<Loaded>` under the read lock and releases it (`Page::with_loaded` via `CloseCell::get`); `close()` takes the write lock, and `CloseCell::close` hands the `Arc` back so `Document::close` frees it after the lock is released. Model-checked by `crates/core/tests/loom_close.rs`. Breaks: `close()` blocks behind extraction (or the reverse); the cache is `!Send` (ADR 40).
- **Signal window.** hayro reports object-depth hits (H2a), skipped content bytes (H10a), decode-limit hits (H10f) and font substitutions (H10e) through *thread-locals*. `open.rs` samples before `Pdf::new` and after the walk; `text/extract.rs` samples four counters (`Counters`) around each page operation. Everything between must stay synchronous on one thread. Breaks: warnings are charged to the wrong concurrent operation or lost (ADR 19, 32). `Pdf::decode_stats()` is a document-wide diagnostic only. `xref_was_repaired()` is re-read after the walk (repair is lazy).
- **Late `XrefRepaired`.** `Page::with_loaded` re-reads `xref_was_repaired()` after every operation and sets a `DocShared` flag; `Document::warnings()` appends one `XrefRepaired`; a page's own `TextPage` never carries it. Breaks: page output would depend on which concurrent page triggered the repair.
- **Concurrent lazy xref repair is fixed by H9, in the fork.** Do not add `try_read/try_write().unwrap()` or asserts back; the scan runs outside the lock, a lookup samples `repaired` with its entry and retries on a stale one. Breaks: panics/aborts under concurrent lookups (ADR 30). Tests: `h9_xref_repair.rs`, `h9_pre_fix.rs` (reverse-applies patch 0010), `concurrency.rs::shared_document_under_lazy_xref_repair`, and `h9_xref_repair.rs::a_lookup_completes_while_repair_is_parked_after_its_scan` (a lookup finishes while a repair is parked between scan and swap, i.e. the scan holds no lock).
- **The brute-force page scan runs only when the walk found no page and did not cut a subtree at `max_page_tree_depth`.** Breaks: it resurrects the pages the cap refused (`deep_page_tree(3000)`).
- **`/Count` is never used, not even as a capacity hint; direct-dictionary `/Kids` are found again by position, only positions < 4096 are accepted; `max_objects` is re-checked after the walk** (a lazy repair can enlarge the xref). Breaks: allocation by attacker-chosen number; quadratic rebuilds.
- **`Document::is_encrypted` is hayro's `Pdf::is_encrypted()`** (parsed trailer), not a byte search. Breaks: `#xx`-escaped `/Encrypt` names are missed.
- **Line assembler (`text/layout.rs`).** Content order; compare with the current line only; thresholds in ems of the *incoming* glyph; `space_gap` 0.149, `gap_break` 0.798, `perp_break` 0.809, `back_break` 0.795, all strict `>`, each strictly inside its probed bracket (ADR 47); angle 2°; blocks on direction change, `block_gap` 1.5 em across, `block_indent` 2 em left, or a boundary marker between the previous line's first record and this line's first. Marker kinds are ignored on purpose (a capped list may hold an end without its start); markers never break lines; blocks matter only for `BlockSeparator::BlankLine`. Synthetic space is suppressed only by an incoming U+0020 or a line ending in U+0020/U+1680/U+3000/U+FEFF — never use `char::is_whitespace` (ADR 48). Breaks: parity with the oracle at the probed rows; rows within 0.01 em of a threshold are tested at six page positions.
- **Text device (`text/device.rs`).** Page space is `initial_transform(false)` (crop-box origin, `/Rotate` applied); the visible box is CropBox ∩ MediaBox mapped the same way, and clip paths shrink it by their bounding box (ADR 46). The device never runs Type 3 glyph procedures, tiling-pattern content or soft masks. Tr 2/6 arrive as Fill then Stroke; the Stroke is dropped by matching the previous call (ADR 53). `/ActualText` goes out at the span's first kept glyph and that record's `advance` is the sum of the span's glyph advances; `Unmapped::Skip` emits no record. `max_chars_per_page` counts code points; a page decodes at most 4 bytes of `/ActualText` per character of that limit, then treats spans as plain marked content; at the cap the device raises the cancel flag and the partial page is returned, while an earlier Ops/Deadline exhaustion stays an error (ADR 33). Boundary markers are capped at `2 × max_chars_per_page + 256`. Glyphs whose geometry overflows `f32` are dropped.
- **Unicode chain (`text/unicode.rs`, T26).** (1) ToUnicode via `Glyph::to_unicode()` with the oracle's control rules (single code point U+0008–U+000D → space; other single controls ignored; multi-code-point verbatim; ADR 49); (2) simple fonts: raw `glyph_name()` → AGL / `uniXXXX` / `uXXXX`; KP15 normalises only WinAnsi 0xA0/0xAD and MacRoman 0xCA on Type 1/TrueType without ToUnicode (ADR 52); (3) UCS2 CMap; (4) reversed embedded `cmap`; (4b) non-embedded Identity CID fonts: Macintosh glyph order for CIDs < 258; (5) unmapped → raw code. **An ignored ToUnicode entry in a composite font leaves the glyph unmapped (raw CID); never fall to 4b.** `agl.rs` is Adobe single-code-point entries only, no TeX names (ADR 51). Sanitising applies to all emitted text after the chain: NUL, C0 except TAB/LF/CR, U+FFFE/U+FFFF, unpaired surrogates → U+FFFD (ADR 50).
- **Content lexer resync (H10a).** A byte that starts no token (stray `)`, `]`, `>>`) is skipped and counted; a failed *operand* (unterminated string, over-deep array) still ends the stream. Breaks: quadratic retry; H2a's pinned behaviour.
- **Codec panic boundary (H18, ADR 86).** hayro-syntax's `filter::guard_codec` runs each call into an image codec crate (zune-jpeg, hayro-ccitt, hayro-jbig2, hayro-jpeg2000) in `catch_unwind` and maps a panic to `DecodeFailure::ImageDecode`, so the image is one `image: decode failed` warning and the page goes on. Only the codec calls are inside: image parameters, `JBIG2Globals` resolution and `Filter::apply` stay outside, so parser bugs still propagate (ADR 35). Code inside the closure may touch only state local to the decode (`AssertUnwindSafe`). It is `cfg(all(feature = "std", not(fuzzing)))`: `cargo fuzz`'s `--cfg fuzzing` compiles it out so fuzzing sees codec panics (`hayro_syntax::CODEC_PANICS_CAUGHT`). The library never calls `panic::set_hook` for Rust callers; their hook runs for a caught codec panic. Test hook: feature `codec-panic-hook` (`arm_codec_panic_for_test` inside the guard, `arm_unguarded_image_panic_for_test` in the codec module just before it, after parameter resolution; per thread, fire once), on in core's and render's dev-dependencies and always in the Python binding. Breaks: a crafted image fails the page (internal #76), or a parser panic is silently swallowed. Tests: `crates/core/tests/h18_codec_guard.rs`, `crates/render/tests/codec_panic.rs`, `codec_panic_hook.rs` (own binary: it sets the process hook).
- **Fonts that fail to load keep their text** (hayro substitutes; H10e counts them; one `font: substituted` warning with a count).
- **Python boundary.** Every `#[pyfunction]`/`#[pymethods]` body, getters included, runs in `guard::guarded`; a new one without it lets `pyo3.PanicException` (a `BaseException`) escape. `crates/testkit/tests/panic_guard.rs` enforces this by a syn source scan: each such fn body must be exactly one tail call to `guarded`; `#[pyo3(get/set)]`, `get_all`/`set_all` and macros inside `#[pymethods]` fail it. It is syntactic and approximate (module init and argument extraction are out of scope). `panic = "unwind"` in every profile, never abort. The panic hook is replaced at module init (else it prints, breaking T48); it also records codec panics that the fork's H18 boundary catches, which no `guarded` unwind takes, so `guarded` clears `LAST_PANIC` on entry and uses a recorded message only if it starts with the unwinding payload's text (a `resume_unwind` re-raise, as `run_parallel` does with a worker's panic, skips the hook); else an `InternalError` could carry a caught codec panic's message. `_panic_for_test(resumed=True)` exercises that path. `_native._arm_codec_panic_for_test()` arms the fork's codec panic hook for the Python tests; error classes are imported and cached at init, never looked up at raise time (a failed lookup there panics outside any unwinding frame and aborts). Non-constant work (`open`, `open_bytes`, `Page.text`, `Page.text_page`, `TextPage.text`) runs under `py.detach`; arguments are converted and buffers copied before detaching. All classes are `frozen` and not `immutable_type` (so `mock.patch.object` works); the module is `gil_used = false`. Test-kit classes hold the builder in a `Mutex` taken only inside `py.detach`. `__init__.py` imports `errors` before `_native` (`# isort: split`). Exception classes are pure Python; attribute-carrying ones define `__reduce__`. Importing `pdf_extract` starts no threads and does no work (T42).
- **Free-threaded support is CPython 3.14t and later.** PyO3 0.29 (pinned exactly) refuses 3.13t; it is not supported and not in CI (ADR 11). Plain `cargo build/test/clippy --workspace` builds `crates/python`, so a Python PyO3 supports (3.8–3.15) must be `python3` on `PATH` or `PYO3_PYTHON`.
- **Tesseract process-wide state (0002 §3.4).** Tesseract and Leptonica have globals; `pxt_global_init` runs once (a `Once`/`OnceLock`) and sets stderr/`debug_file` silencing before any instance exists; no instance may change process-global parameters: `Instance::with_variables` refuses any name Tesseract's own `GlobalParams()` knows (asked through the shim's `pxt_is_global_param`, not a list) and the per-instance names in `REFUSED_INSTANCE_PARAMS` (file-opening, training/dump/box modes, model selection such as `tessedit_ocr_engine_mode`/`tessedit_load_sublangs`; re-audit at every Tesseract upgrade, ADR-0082 addendum) with `InvalidArgument`; a model's own `lang.config` is not constrained (trusted). Language lists must match `[A-Za-z0-9_]+(\+[A-Za-z0-9_]+)*`, and `pxt_init` fails with `InitFailed` if a requested language is absent from `GetLoadedLanguagesAsVector()` after `Init`. The helper's descriptor marking (`pipe.rs`) is `close_range(CLOEXEC)` on Linux and otherwise the `sweep_cloexec` loop over `first..sweep_bound`; the bound is a plausible `sysconf(_SC_OPEN_MAX)`, else the soft `RLIMIT_NOFILE`, clamped to `MAX_SWEEP = 1<<20`, and is never empty. Without `close_range` (macOS, Linux < 5.11) a descriptor at or above the bound stays inheritable (a host that lowered its soft limit below a descriptor it holds; anything ≥ `MAX_SWEEP`): a documented carve-out (spec 0003 §2.2, F21), not a defect. Tests exercise the loop through `sweep_cloexec` over a bounded range, never `mark_cloexec_from`, which would flag every descriptor above the test's own. Breaks: output on fd 1/2 (O40) and set-once violations. Only the shim catches C++ exceptions; never bind `capi.h` (D-5).
- **Vendored Tesseract build.** `DISABLED_LEGACY_ENGINE=ON`, graphics off, OpenMP off, no codecs, no native SIMD (D-4); so `EngineMode::TesseractOnly`/`TesseractLstmCombined` fail with `InitFailed`, and `oem` defaults to `lstm_only`. The system-tesseract build is verified only for the engine and pool (it may be OpenMP-built and oversubscribe).
- **Fork-hazard lock list (0002 §2.4, 0003 §1.1).** The deliberate absence of `atfork` handlers is only safe because the hazard is documented, so the set of process-wide locks that a fork can leave held must stay enumerated in the crate docs (`# Forking` in `pdf-extract-ocr`), the Python docstrings, README and the residual below: the `default_ocr_engine()` `OnceLock`, tesseract-sys `GLOBAL_INIT`, an engine's pool mutex, the process-isolation client's `LOG` and `TEST_ENV` mutexes, and the tessdata `OVERRIDE` lock. A new process-wide lock or `OnceLock` in the OCR crates joins that list in the same commit; `crates/ocr/tests/docs.rs` greps for it.
- **A timeout is `Recognize == -1` and our clock past the deadline** (D-11); any other `-1` is `Recognition`.
- **H13 image cap lives in hayro-syntax `DecodeLimits`**, checked on declared dimensions, on each codec's header dimensions before it allocates, and on reported dimensions (D-8). A codec change must keep all three.
- **H14/H15 codec memory budgets (run 0003 §1.2).** One cumulative per-decode byte budget derived from `max_image_pixels` (no `Limits` field): `JBIG2_BUDGET_BYTES_PER_PIXEL = 2`, `JPX_BUDGET_BYTES_PER_PIXEL = 64`, in hayro-syntax `filter/mod.rs`; `max_image_pixels: None` means no budget. H23 adds a second JBIG2 allowance from the same knob, `JBIG2_WORK_PIXELS_PER_PIXEL = 16` (`DecoderContext::work_budget`, carried in the same `MemoryBudget` handle): each symbol instance a text region or aggregate symbol places costs its symbol's unclipped area + 64, and a refusal (`OverflowError::WorkBudget`) takes the memory budget's path to `ImageMemoryLimit`. Each charge happens *before* the allocation it governs, never refunded, reset per `decode` call. A refusal is `DecodeFailure::ImageMemoryLimit` → `InterpreterWarning::ImageMemoryLimit` → `WarningKind::ImageMemoryLimit` and the image draws nothing; a JPEG 2000 tile-count overflow is `ImageTooLarge` → `ImageDecode`, not a memory-limit hit. The enforcement is code inside the vendored codecs: a rebase of either crate that drops patches 0023–0025 silently lifts the bound (`check-patches.sh` catches drift, not a forgotten rebase). The multiplier margins are thin for JPEG 2000 (1.5× at four components), so a new decoder allocation site needs a charge and the measurement in 0003 Appendix A.5 repeated. `hayro-jpeg2000` must stay 0.3.x.
- **Noise pre-check (`crates/ocr/src/precheck.rs`; 0003 §1.3).** Runs only when `OcrConfig.noise_precheck` (default true; Python `noise_precheck=`) and rendered dpi ≥ `MIN_DPI` (144), after the budget check and before the backend call, for every backend; its time is charged to the page budget (`engine.rs::screen_within`: a screen that finishes at or past the deadline is a timeout, never a recognition on a spent budget). The verdict is Tesseract's own Otsu split replicated, judged on **Tesseract's foreground side** (the side it binarises as ink), never on its class alone: `Speckle` iff not `Empty`, foreground ≥ 1 % and isolation ≥ 0.5 × (1 − p)⁴. Exactly one 2 × 2 downsample, re-check, else skip (empty OCR `TextPage`, `dpi()` unchanged); a downsampled page reports `dpi() == dpi'/2` with coordinates mapped by the exact factor 2. Warnings: `ocr: noise-dominated …` on the `TextPage` and `page N: ocr: …` rows in `Extraction.warnings` (page order, after page-limit warnings). The code stays pure Rust, `forbid(unsafe_code)`, and loads no Leptonica (O29: the parent under `Isolation::Process` loads no native OCR code). Thresholds are constants, not configuration. Breaks: reverting to "class `None` ⇒ speckle" skips real text on banners/figures/inverted halves.
- **Licensing.** Our code is `GPL-3.0-or-later` (`LICENSE`, every workspace `Cargo.toml`, `pyproject.toml`); dependencies stay permissive-only (L1). `deny.toml` has `[licenses.private] ignore = true`, which exempts only `publish = false` workspace members: every workspace crate must stay `publish = false` and the allow-list must never gain a copyleft entry. cargo-deny ≥ 0.18 has no `copyleft` key; the allow-list rejects GPL/LGPL/AGPL by construction (`tools/license/check-deny-rejects-copyleft.sh`). Everything shipped is GPLv3-compatible (hayro and PyO3 `Apache-2.0 OR MIT`, Adobe AFM/AGL BSD-3-style, the rest MIT/Apache-2.0/BSD/ISC/Zlib/Unicode-3.0). Consumer note: a distributed work combining the wheel falls under the GPL's source-availability obligations; use inside one organisation without distribution does not (ADR 9). The wheel ships `LICENSE`, `THIRD_PARTY_NOTICES`, `crates/testkit/data/README-AFM.txt` and `tools/license/rust-std-COPYRIGHT.html` via `license-files`. `THIRD_PARTY_NOTICES` is written by `tools/license/gen-notices.sh` and never edited by hand (ADR 54): part 1 is cargo-about 0.9.2 (`about.toml`, template `tools/license/about.hbs`) over `crates/python`'s graph without dev/build dependencies, accepting deny.toml's list in deny.toml's order (so dual-licensed crates ship MIT, with the crate's own licence file; some upstream MIT files carry no copyright line). A crate with no file for the licence cargo-about picks would get the SPDX template with `<year> <owner>` unfilled, so `about.toml` clarifies those (brotli-decompressor to its BSD-3 `LICENSE`; alloc-stdlib, which ships no file, to the sibling alloc-no-stdlib 2.0.4 `LICENSE` from the same upstream repo, checksum-pinned) and `license.rs` fails on any unfilled placeholder; part 2 is the Adobe Glyph List notice from `tools/license/agl-notice.txt` (it also covers the AGL table read-fonts compiles in); part 3 copies verbatim, at generation time, the notices of data that dependencies `include_bytes!` and cargo-about cannot see (hayro-interpret's `LICENSE_FOXIT` for the 14 Foxit `.pfb` fonts, its `assets/README.md`, `CGATS_LICENSE.txt`, a statement that `LAB.icc` ships under hayro-interpret's `Apache-2.0 OR MIT`, hayro-jpeg2000's CC0 `assets/README.md` and `assets/LICENSE.txt` for its three embedded ICC profiles, and hayro-cmap's Adobe CMap `assets/LICENSE.txt`; the two registry crates are located via `cargo metadata`). The script sets `LC_ALL=C` so glob order is locale-independent, and sorts each licence's crate list by name (cargo-about lists path crates before registry crates). ## Landmines

- **Never edit `vendor/hayro-*` without exporting; the same holds for `vendor/{tesseract,leptonica}`** (export with `tools/vendor/export-c-patches.sh`; `check-c-sources.sh` fails otherwise). Every change is its own commit, then `tools/vendor/export-patches.sh` and commit the patch files, or `vendor-patches` fails. The hayro crates are `=`-pinned in `crates/core/Cargo.toml`; hayro-jpeg2000 must stay 0.3.x (hayro-syntax 0.7.2 requires ^0.3.5). Export needs the pristine tags `vendor/hayro-pristine-1`, `vendor/hayro-pristine-2` and `vendor/{tesseract,leptonica}-pristine-1` (one commit, both C tags). They were local-only at first and are pushed to origin with the work that adds them; in a clone that lacks one, fetch tags or pass the "Vendor pristine …" commits as BASE1/BASE2. The hayro series is exported in **two ranges**: `pristine-1..pristine-2^` over the three original crates, then `pristine-2..HEAD` over all five, numbered continuously; the tag-2 commit must hold only the pristine codec import (it is never exported), and a rebase that rewrites it must move the tag. `export-patches.sh` rewrites the whole series every run (there is no incremental export; range 2 is numbered on from range 1's last patch with `--start-number`); range 1's `[PATCH n/N]` headers say `n/22` however long range 2 grows, so those patches stay byte-identical; range 2 is numbered on from 23 and its totals include the offset (`23/34`…`34/34` today), so adding a patch rewrites the earlier range-2 headers, and it refuses a merge commit as the second tag.
- **Vendor imports must land by merge commit, and the pristine tag must stay reachable.** `vendor/*-pristine-N` tags name the import commit; squash-merging the PR that adds one (or rebasing it) leaves the tag on a commit that is not in `main`'s history, and `check-patches.sh`/`export-patches.sh` lose their base (both exporters now refuse a base that is not an ancestor of HEAD, so a squashed import fails loudly instead of exporting the wrong series). Land import PRs with a merge commit; after any rebase of the stack, move the tag onto the rewritten import commit before exporting, and push the tag with the work. The import commit must hold only the pristine tree (it is never exported).
- **Standalone offline harness builds need the workspace `[patch.crates-io]` entries.** `crates/core/tests/h9_pre_fix.rs` builds a pre-fix copy of hayro in a temp project from the workspace `Cargo.lock`, offline. The lockfile names the vendored codecs without a registry source and cargo resolves optional dependencies even when disabled, so the harness manifest must carry the same `[patch.crates-io]` entries as the root `Cargo.toml` (see the comment there); vendoring any further dependency of hayro-syntax means editing both.
- **Fixture and patch counts are quoted in prose and tested.** `crates/testkit/tests/fixtures_manifest.rs::docs_quote_the_manifest_fixture_counts` asserts the count phrases in README.md and the tests/fixtures row above ("295 synthetic and 60 real-world", "8 encrypted + 287 generated, 295 manifest entries", "OCR: 40 committed", "12 noise variants", and README's "twelve noise variants"); `docs_quote_the_vendor_patch_counts` does the same for the `vendor/` row's "patches 0001–0034" and the `vendor-patches` row's "five hayro rows, 34 patches", counted from `vendor/patches/hayro/` and `vendor/PROVENANCE.md`. A doc edit that changes a count must update the manifest or the patch series, or vice versa.
- **Changing any test-kit byte output changes fixture SHA-256s.** Regenerate and update `tests/fixtures/manifest.toml` in the same commit. Output of the builder is deterministic; encrypted fixtures are the exception (random `/ID`): regenerate with `mkfixtures.py enc`, which rewrites their manifest and provenance rows.
- **Oracle probes must save and reopen the document.** An unsaved in-memory PyMuPDF document extracts text from OFF optional-content groups; the saved one does not (ADR 44). `gen.py --prune` must name corpus-c and corpus-b together or the other corpus's expectations are deleted.
- **The oracle's `get_text_length` knows only Latin-1:** for WinAnsi 0x80–0x9F it returns 278 units, not the rendered width. `text_width` follows the AFM; `afm_oracle.rs` pins the artefact.
- **`crates/testkit/data/README-AFM.txt` is Adobe's notice verbatim, trailing spaces included.** Do not let an editor strip them.
- **The `compile_fail,E0599` doctest** on `Page::with_loaded` (`crates/core/src/page.rs`, compiled only without `render-support`; the `rust` job runs `cargo test -p pdf-extract-core --doc`) proves the render hook is absent only in that it fails to compile: stable rustdoc does not check the `E0599` code, and there is no positive companion doctest, so a failure for another reason would also pass.
- **Thresholds sit in brackets a few thousandths of an em wide** (`space_gap`: 0.0023 em). Tuning stays inside the brackets and requires gates B and C to be re-run; the oracle itself decides noise-level cases by its own f32 rounding (ADR 47).
- **Debug-build stack.** The 256-deep cases need the dev-profile `opt-level` settings (vendored and font crates 2, `pdf-extract-core` 1); op-count tests use small caps because hayro runs ≈0.9M ops/s in release and ≈60k/s in debug. The time guarantee is `page_time_budget`, never the op cap (ADR 27).
- **Fixtures with CID fonts must carry a `/FontDescriptor`** (without one the oracle emits raw bytes, KP22).
- **Unit-test modules** sit beside their file as `*_tests.rs`; `text/tests/` reuses `tests/common` via `#[path]`.
- **Warning details are shared constants** in `core/src/text/details.rs`. Six reachable kinds (form cycle, interpreter nesting, object depth, stream decode limit, font substitution, damaged content) are tested by comparing the emitted detail with the shared constant; the identical-copy source scan in `text/tests/limits.rs` remains only for the four kinds core text extraction cannot raise (`UnsupportedFont`, the three image kinds). `the_nesting_detail_states_the_interpreters_cap` ties `INTERPRETER_NESTING_DETAIL`'s "N levels" to the interpreter's cap (hayro's crate-private constant), so a hayro bump that changes the cap fails there (internal #158).
- **Along/perpendicular asymmetry at 0.8 em:** an along gap and a perpendicular rise of exactly 0.8 em are classified oppositely by design (brackets abut at 0.8); do not "fix" it.

- **Render golden hashes must be re-blessed on any hayro/vello/pic-scale lockfile bump** (`crates/render/tests/render-golden/`). Determinism is exact per host; cross-OS agreement is tolerance-gated (≥ 99.9 % identical pixels, |Δ| ≤ 8; D-12) by the `render-cross-os` job.
- **Linux golden bootstrap.** Linux hashes (`*.linux.sha256`) cannot be made on a Mac: a first run on ubuntu fails the golden test, and the `render-golden-ubuntu-24.04` (and `-macos-14`) CI artefacts are committed, then CI is rerun. The `cargo test` CI steps run with `--no-fail-fast`, so a golden failure does not stop later test binaries and the artefact upload still has files.
- **Dev-profile opt-levels are what make 512 KiB stacks and OCR tests work.** `hayro`, `vello_cpu`, `vello_common` (the renderer's recursion is monomorphised in hayro), and for corpus D's noise builder `pdf-extract-testkit`, `sha2`, `miniz_oxide`, `moxcms`, `pic-scale`, `zune-jpeg` carry `opt-level` in the workspace `[profile.dev.package.*]`. Unpublished crates only; a dependent workspace would lose the guarantee. The vendored Tesseract builds Release even in a debug build (≈ 1 s/page).
- **Build wheels with `tools/build/build-wheel.sh`, never a bare `maturin build`.** The script stages the helper and passes the generated SBOMs; a bare build has neither (maturin's own Rust SBOM is off on purpose, ADR 0091), and `verify_wheel.py` rejects the result. Linux wheels need `--docker <arch>` (the manylinux_2_28 image); the container's cargo state lives in `target/docker-<arch>` and `target/manylinux-<arch>` (several GB). On macOS, uv may also know an x86_64 (Rosetta) CPython; the script refuses a non-arm64 interpreter (set `PDF_EXTRACT_WHEEL_PYTHON`).
- **CI build traps the wheel tooling already hit.** maturin's sdist stores every file 0644, so scripts are run through `bash`, never by their execute bit. `ci.yml` sets `CARGO_TERM_COLOR=always`, which put escape codes into SBOM URLs until `sbom.py` passed `--color never` to `cargo tree`. Swatinem/rust-cache prunes files it does not recognise inside `target/`, so a cached `target/wheel-tools` venv can come back half-deleted; `build-wheel.sh` reuses it only if `maturin --version` runs. `workflow_dispatch` only works for a workflow file already on `main`.
- **The package version is the workspace version.** `pyproject.toml` declares it `dynamic`; bump `[workspace.package] version` in `Cargo.toml`, never pyproject. The helper's handshake compares crate versions.
- **`uv sync` removes the editable `maturin develop` install** (the package is not a uv project member); rerun `uv run --no-sync maturin develop --release` after any `uv sync`/`uv add`.
- **Python's default OCR engine is the binding's, not the Rust crate's (ADR 0092).** `crates/python/src/ocr.rs::default_engine` owns a `OnceLock` built with `Isolation::Process` and `helper_dir` = the package directory; `pdf_extract_ocr::default_ocr_engine()` stays in-process and is never called from Python. `OcrEngine(isolation=...)` defaults to `"process"` in Python only, so Python tests about in-process behaviour must pass `isolation="in_process"`, and tests that use the default engine need `@needs_helper`. A missing helper is a stored `engine_not_built` (no fallback).
- **Stage the helper before `maturin develop`:** `tools/build/stage-helper.sh` (takes the binary's path from cargo's JSON artifact messages, so `--target`, `--target-dir`, `CARGO_BUILD_TARGET` and `CARGO_TARGET_DIR` work; `--profile <name>` replaces the default `--release`; `tools/build/test-stage-helper.sh` tests that argument handling with a fake cargo) then `uv run maturin develop`; otherwise `OcrEngine(isolation="process")` raises `engine_not_built`. The Python coverage job builds an instrumented helper.
- **`PDF_EXTRACT_TESSDATA=<dir>` switches `quality.rs` to report-only measurement mode** (no model pin check, no gates, no process pass). Do not set it in CI; locally it relaxes the quality gate. Outside that mode the gate skips (green) with a message when no tessdata resolves, unless `CI` is set, where it fails; and it fails once, up front (`quality/model_pin.rs`), when the resolved model's SHA-256 is not the pinned one, naming the directory, how it was chosen, both SHAs and the remedy `TESSDATA_PREFIX=…/tools/oracle/.cache/tessdata_fast`.
- **Corpus D noise is built, not committed** (D-9, D-22). Never regenerate it with numpy; the builder (`testkit::corpus_d`, integer Irwin–Hall, seed 20261003, unfiltered streams) must stay byte-stable across hosts, and its SHA-256s are pinned in `manifest.toml` `[[built]]`. A drift fails `quality.rs` naming the file and the re-pin steps (`mkcorpusd.py --pin-built`). `gen.py --prune` with `--ocr` and no `--built` is refused when a built expectation is in `--out` (it would delete it); name `--built` too.
- **Python 3.11's `Thread.join` returns before the OS thread is gone,** so thread-count tests (`tests/python`, `crates/core/tests/extract_threads.rs`) settle (poll) before comparing counts or `/proc` thread totals. The Rust poller (`crates/core/tests/thread_poll/`, Linux only) is a directory module shared by two test binaries (`extract_threads.rs` must be the only test in its binary, so the panic-propagation test is `thread_poll_panic.rs`); a drop guard stops the poller when the closure under test panics, otherwise `thread::scope` would hang the test instead of failing it.
- **The `ocr-system` job excludes the fork and silence tests** (Ubuntu's OpenMP Tesseract is not usable in a forked child, and silence is a vendored-build claim).
- **Wordlist:** `cargo test -p pdf-extract-testkit --test wordlist` runs over the whole tree, including specs and ADRs.
- **An on-demand PR run (`gh workflow run ci.yml --ref <branch>`) tests the branch tip, not its merge with `main`.** A branch that is behind `main` can pass and still fail on `main`; rebase or merge `main` first when the change interacts with recent work. A red run on `main` is the first signal for a merged batch, and fixing it is part of that batch (ADR 85).
- **Heavy Linux jobs need `.github/actions/free-disk`.** The `rust`, `coverage` and `python-coverage` jobs build the workspace's tests more than once (or instrumented) on a ~3 GB-free ubuntu-24.04 runner; without the action the linker dies with SIGBUS, which does not look like a disk problem. A new heavy Linux job runs it after checkout.
- **`threading.stack_size(512 KiB)` does not guarantee a 512 KiB stack on Linux.** glibc serves new threads from its cache of exited threads' stacks and accepts a block up to 4× the request, so after Rust's 2 MiB worker threads (`extract(workers=...)`) exit, a 512 KiB thread can get 2 MiB (internal issue #70). `tests/python/pdfs.on_small_stack` therefore measures each thread's real stack (`pthread_getattr_np` / `pthread_get_stacksize_np`) and parks oversized ones until it gets the requested size; `test_small_stack.py` asserts the real size on Linux and macOS. The Rust integration tests get the same check from `crates/core/tests/common/stack.rs` (`on_small_stack`; the render tests include that file by `#[path]`; `tests/stack_size.rs` tests the runner); it needs `unsafe` pthread FFI, so it cannot live in the `forbid(unsafe_code)` testkit or in core's library code. Core's own unit tests (`src/text/tests`) include the same file by `#[path]` under `#[allow(unsafe_code)]`, which the unit-test build permits because core is `deny`, not `forbid`, there (ADR 0089; `text::tests::the_unit_tests_small_stack_is_measured` pins it); any further `allow(unsafe_code)` under `cfg(test)` widens that exception. Off Linux and macOS the measurement is taken on trust (`stack_fits(None)`), and CI runs only those two.

- **Only the close cell and the pool's lock/condvar go through the `sync` shims.** loom types panic outside a `loom::model` run and loom forbids statics of its types, so anything a `static`, the open pipeline or engine code outside the model touches stays `std` (the factory `Arc`, `FORK_RESETS`, the `Pages` cursor, the lazy-repair flag). Shimming more makes the loom build unusable; shimming less means loom checks a copy. `CloseCell` and `Pool` are `pub` in private modules only so the loom build can re-export them. A change to either protocol must keep `tests/loom_close.rs` / `tests/loom_pool.rs` passing (run them as in the `loom` CI job: `RUSTFLAGS="--cfg loom" LOOM_MAX_PREEMPTIONS=3 cargo test -p pdf-extract-core --test loom_close --release`, likewise `-p pdf-extract-ocr --test loom_pool`; a separate `CARGO_TARGET_DIR` avoids rebuilding the normal target on every switch).
- **The pool's pid source is a field (`fn() -> u32`, `std::process::id` from `Pool::new`).** `check_pid` must call it, not `std::process::id` directly, or the loom fork cases stop staging a fork. A fork reset frees every slot and calls `notify_all`; the generation-mismatch return in `Slot::drop` deliberately notifies nobody (it changes no count), which loom showed is only safe because the reset itself wakes the waiters.

## Where to change X

- A new hayro behaviour: edit `vendor/hayro-*`, own commit, `export-patches.sh`, test in `crates/core/tests/h*_*.rs`; record an ADR.
- Glyph→Unicode rules: `core/src/text/unicode.rs` (+ `agl.rs`); add a corpus-C recipe in `crates/testkit/tests/common/corpus/` and re-run the oracle.
- Line-assembly thresholds / block rules: `LayoutParams` in `text/options.rs`, logic in `text/layout.rs`; sweeps in `tests/text_layout.rs`.
- A limit or warning kind: `limits.rs` / `warning.rs`, mapping in `open.rs` or `text/extract.rs`, Python mapping in `crates/python/src/{errors,limits}.rs`, stub `_native.pyi`, `tests/python/stubtest-allowlist.txt` if needed.
- A Python method: wrap in `guard::guarded`, detach if non-constant, update `_native.pyi` and `python/pdf_extract/__init__.py`.
- A fixture: add a recipe to the corpus catalogue (it owns the fixture's gate), run `cargo run -p pdf-extract-testkit --example corpus_c`, then `tools/oracle/gen.py`; `PARITY_BLESS=1` rewrites snapshots.
- An OCR behaviour: engine/pool in `crates/ocr/src/{engine,pool,tesseract}.rs`; C++ in `crates/tesseract-sys/csrc/shim.cpp` (every `pxt_*` must be referenced by a test; `shim_symbols`); helper protocol in `isolation/wire.rs` (compiled into both sides); Python surface in `crates/python` and `_native.pyi`.
- The noise pre-check: rule and constants in `crates/ocr/src/precheck.rs`, application (downsample, dpi/scale mapping, warnings) in `OcrEngine::ocr`, notes in `core/src/extract.rs`; `quality.rs` pins verdicts per page and writes `ocr-report.json` (and `ocr-report-precheck-off.json` with `PDF_EXTRACT_NOISE_PRECHECK=0`).
- A new call into an image codec crate from hayro-syntax: wrap it in `guard_codec` (H18), nothing around it; extend `crates/render/tests/codec_panic.rs` if it is a new codec.
- A codec memory charge: edit `vendor/hayro-jbig2` or `vendor/hayro-jpeg2000` in its own commit, re-export, and test through hayro's API in `crates/core/tests/h14_jbig2_budget.rs` / `h15_jpx_budget.rs`; the sites are listed in 0003 Appendix B.2.
- A behaviour change: an OpenSpec change (`openspec new change`) whose delta specs modify the owning capability in `openspec/specs/`, archived when it lands. Do not edit `docs/specs/0001`–`0003`; they are run history. Each behaviour has one owning capability; the others refer to it by name.
- A decision: new file in `docs/adr/` with the ADR index script (`adr_index.py --next`, then regenerate the index); supersede, never rewrite.
- A fixed fuzz finding: commit its minimised input as `fuzz/regressions/<target>/<first 16 hex of its SHA-256>` with the fix (see **Fuzzing**).
- A new `Limits` field: give it a fuzzing value in `core/src/fuzz_api.rs::fuzz_limits` (a struct literal, so the build fails until you do).

## Parity residuals

Differences from the oracle that are documented, not findings (spec §2.5 is
authoritative; this is its pickup copy). Gate B on corpus B (60 files, 91
pages): all open, routing agreement 1.000, similarity median 1.000, p10 0.968,
exact after strip 0.879, line-count delta mean |Δ| 0.13, max 3; no
`LayoutParams` tuning was done.

- **Right-to-left scripts** (`BidiSample`, `hello3`, `FC60_Times`): oracle reorders Arabic/Hebrew runs to logical order; we emit content (visual) order. Largest gap on B (similarity 0.14–0.77).
- **Tiling-pattern text** (`pattern_tiling_with_text`): the oracle extracts glyphs drawn by a pattern's own content; the device never runs pattern content.
- **Widget appearances the oracle synthesises** (`acroform`): checked check boxes (U+0014) and unsigned signature fields (`SIGN`); we use `/AP` as written and skip a state-dictionary `/N`. Likewise FreeText without `/AP`: the oracle synthesises from `/Contents` and `/DA`, we emit nothing.
- **Anisotropic scaling** (`CombTest`): the oracle's font size is the geometric mean of the x/y scales (11.078 vs our 10.82 pt), so a gap of 0.799 em there is 0.818 em here; no in-bracket `gap_break` closes it.
- **Combining marks placed with kerns** (`GlyphLayoutDIN91379`): a backward kern on the mark and forward kern on the base leaves a 0.18 em gap; we insert a space.
- **ToUnicode → U+FFFD** (one observation): the oracle ignores it and uses the raw code; we take U+FFFD.
- **Codes without a glyph in a non-embedded standard-14 font** (`embedded_zip`): a literal LF advances the oracle's pen by 0.278 em; ours differs; a line running off the page is cut at a different character. Belongs with standard-14 glyph widths (Foxit substitutes with AFM-compatible advances).
- **Controls in ToUnicode:** Type 1, TrueType, Type 0 and Type 3 match the oracle; an ignored entry in a simple font falls to the glyph name without KP15 normalisation (unprobed vs oracle); unprobed: ignored entry in a font with an embedded program or known collection, at a KP15 position, multi-code-point entries holding C1/U+007F.
- **Deliberate differences:** Tr 4–6 emitted once (KP14); NUL/C0 → U+FFFD (KP6, D-10); duplicate leaves and cycles collapsed (KP10); page-tree nodes deeper than 256 are skipped (KP23; the oracle has no cap); Form XObjects nested deeper than 50 stop (KP21; oracle ≥ 60); text without `Tf` is extracted by us, dropped by the oracle (KP18); `/ActualText` edge cases (KP17); CID fonts without `/FontDescriptor` (KP22).
- **TeX glyph names** (`parenleftbig`, `summationtext`): unmapped (raw code) with no ToUnicode; `square` stays raw where the oracle gives U+25A1 (`kp06_type3_square`). A `/Differences` `nbspace` at 0xA0 under WinAnsi is normalised by us, kept as U+00A0 by the oracle.
- **CID fonts:** embedded CIDFontType0 with Identity, no ToUnicode and a non-standard charset; non-embedded Identity beyond the 258 Macintosh names; custom orderings; CJK where UCS2 and MuPDF disagree; skrifa ignores (3,0) symbolic and Macintosh cmaps for the reversed-cmap step.
- **Fonts that fail to load:** text kept; the substitute's widths may differ, so clip classification near edges can. **Type 3:** glyph size/advance from `FontMatrix`/`/Widths`; MuPDF may size from the procedures. **Glyph boxes** within ≈0.1 em of a clip or MediaBox edge may classify differently.
- **Threshold boundaries:** only noise-level gaps (≈1e-6 em) around the thresholds differ; the along bracket [0.7955, 0.8) and perpendicular bracket [0.8, 0.8182) abut at 0.8 em.
- **Hostile inputs:** the oracle's text for over-deep objects depends on where the nesting sits (empty, partial, or an error); we gate on warning kind (ADR 16).
- **Damaged content:** both parsers resync, at different points; we do not recover from a failed operand or an instruction with more than 10 operands. **Encryption** hayro rejects (unusual `/V 4` crypt filters) raises `UnsupportedEncryptionError` where the oracle opens. **xref repair** outcomes on heavily damaged files.
- **Resolved in run 0002:** a catalog whose `/Pages` is a direct dictionary now opens (H11, patch 0020; corpus-C `catalog_direct_pages`), and a Form XObject's `/Resources` referencing the page's own resources object, and named properties through shared/inherited resources, resolve (H12, patch 0021). Q7 is no longer `Corrupt`. Inherited P1 conflicting with a form's named `/Resources` is oracle-checked end to end by corpus-C `ocg_form_precedence_*`; the rule is that the innermost form's own `/Resources` wins, then its parents' (ADR 0074 addendum).

Robustness residuals (spec §2.4): peak memory per extraction is bounded only by
`max_stream_decoded_bytes × live decoded streams`; a single operator (a 256 MiB
decode, a font or CMap parse, the H6b reverse-cmap build) is not interruptible;
concurrent lazy repairs may each scan the whole file (N× memory); cross-kind
interpretation cycles repeat up to 50 times; `_native` module init is unguarded;
TOCTOU at open; allocation failure aborts; inline images and `FromBytes`
bypass decode limits (unreachable on the text path); the predictor allocates
from dictionary values. Sanitizer and fuzz coverage is on demand and local, not
per push (ADR 0087); open findings are filed as issues (none was open when this was written: internal #115, #116, #119 and #120 are fixed, H19–H23, and internal #121 by H24, ADR 0090). A lazy xref repair after open that replaces the catalog makes core's index silently drop an inline page-tree root's inherited `MediaBox` and `Resources` (a missing font falls back to Helvetica, with no warning), so a page's result depends on whether an earlier operation triggered the repair; pinned as characterization, not endorsed (ADR 0075 addendum).

OCR residuals (0002 §2.2, §2.4, §2.5; not defended):

- **Fork deadlock.** A `fork()` while another thread is inside the first `default_ocr_engine()` `OnceLock` or the tesseract-sys `GLOBAL_INIT` `OnceLock`, or holds the pool mutex, the client's `LOG` or `TEST_ENV` mutex, or the tessdata `OVERRIDE` lock, deadlocks the child (reproduced for the `OnceLock` and the pool). Rules: build every engine (the default one too) before forking; do not fork while another thread may be inside OCR; prefer `posix_spawn`/`exec`; in Python use the "spawn" or "forkserver" start method. Documented in the `pdf-extract-ocr` crate docs (`Forking`), the README and the Python docstrings; no atfork handlers are installed (THEORY.md says why). A child that sees a pool built before the fork abandons it (O30).
- **Codec memory (H14/H15) is bounded, not eliminated.** What is not counted: fixed context tables, allocations linear in the input (bounded by `max_file_size`, except a JBIG2 segment header's referred-to list, up to 2 GiB and bounded only by `max_stream_decoded_bytes`, and `hayro-ccitt`'s MMR vectors, about 1–2 MiB per region: ADR 0079 addendum 2026-10-21), JPEG 2000's sort scratch (about half the precinct list) and a reused `DecoderContext`'s leftover capacity (hayro-syntax never reuses one); JBIG2's charged `Vec`s may reserve up to 2× the charged size, so peak ≤ 2 × budget + uncounted. A legitimate file can be refused: the budget is cumulative and never refunded, and a JBIG2 dictionary of ~5,000 Huffman-coded aggregate symbols exceeds it at the default cap. A JPEG 2000 image tiled into 1 × 1 code-blocks costs about 242 B/px against the 64 B/px estimate and is refused above roughly a quarter of `max_image_pixels`, deliberately (0003 A.5; ADR 79). CPU time inside one decoder call is *not* bounded by `page_time_budget`, which is checked only between operators: a decoder loop that does not terminate spins for good (ADR 88; the JBIG2 export-flag loop did, internal #94, and so did the height-class loop, internal #116; H17 refuses export flags that stop advancing once the arithmetic data is used up, and H22, a heuristic, refuses a dictionary once the data is used up and more than 64 height classes in a row decode no symbol; those two loops are the only data-terminated JBIG2 loops guarded), and H23's work allowance (ADR 79 addendum) bounds the time JBIG2 spends placing symbol instances (text regions and aggregate symbols; a halftone region's grid cells × pattern area is not charged), so every other decoder loop is bounded only by its own termination or by the allocations the memory budget charges; CCITT/DCT/RGBA conversion rely on H13 alone; stack depth and the `unsafe` in `fearless_simd` paths are untouched.
- **Noise pre-check is an approximation (0003 §2.3).** A noise-dominated page can be made to skip OCR (denial of recognition, not of service); correlated noise (grain > 1 px at the rendered dpi) has a connected foreground, is `Clear` and can still stall (a 2 × 2-block noise field cost 7 s) until `page_timeout`; photo/gradient pages go to Tesseract and may return junk text; speckle-like real content (halftones, stippling, dense dotted leaders) is downsampled or skipped; nothing runs below 144 dpi; constants come from one synthetic corpus plus 29 rasters, heavy noise (σ ≫ 12) with much text is unmeasured. A skipped page counts as an OCR success with empty text.
- **Timeout lateness.** Tesseract's deadline is not checked during layout analysis; a 1 ms deadline on 2000² noise returned after ≈ 3 s, so a timeout can be late by a whole layout pass. In process mode the parent's `poll` kill is exact. A deadline that expires between the engine's post-screen check and `Instance::recognize` gets the sys crate's zero-remainder `Timeout` refusal, which `pool::run` treats like a monitor stop (the instance is dropped): timing tests cannot tell the two apart for one attempt (0002 §2.4).
- **In-process `abort()`/`ASSERT_HOST`** ends the process (same exposure as PyMuPDF); only `Isolation::Process` contains it. A hostile `traineddata` is trusted. Helpers are not sandboxed; a SIGKILLed parent leaves helpers to exit on EPIPE; `SIGPIPE` (writes to a dead helper cannot raise it in the host: `F_SETNOSIGPIPE` on macOS, blocked and consumed on Linux); `fork()` mid-page window; respawn startup is allowed `max(page_timeout, 60 s) + 2 s` outside the page budget.
- **Cross-host pixels differ** (SIMD dispatch); OCR text is compared by CER, never exactly. Text parity with the oracle's OCR is not a goal.
- **Quality:** `tessdata_fast` is the recommended and CI model (docs/reference/tessdata-measurement.md); Tesseract splits the number column of lists; noise at 300 dpi is worse than at 72 for the noisy sparse page.
- **`system-tesseract`** links whatever pkg-config finds (OpenMP, version, output are outside our control).

## Fuzzing

Design D6–D8 of `openspec/changes/harden-fuzzing-sanitizers-loom`; spec
capability `fuzzing`. Long fuzzing is local; CI never fuzzes on push.

- **Layout.** `fuzz/` declares its own `[workspace]` and commits its own
  `Cargo.lock`, so libfuzzer-sys and nightly stay out of the stable build,
  `cargo-deny` and the shipped lock. `fuzz/rust-toolchain.toml` pins
  `nightly-2026-10-01` (with `rust-src`, `llvm-tools`); bump it in a dedicated
  commit, at least two weeks old. Its `[patch.crates-io]` copies the root's
  hayro entries with `../` paths, so the targets run the patched fork;
  `check-patch-sync.sh` fails CI when the two drift.
- **Targets and drivers.** `open` (open + page count), `text` (`text_page` of
  the first 6 pages and the last), `render` (page 0 at 36 dpi), `cmap` (`hayro_cmap::CMap::parse`
  with `load_embedded` for `usecmap`; input starting `bcmap`, hayro-cmap's private binary format, is dropped first because the interpreter refuses it from a document (H24, ADR 0090), so hostile input reaches only the text parser), `unicode` (selector byte + payload into
  the `text/unicode.rs` fallbacks). Four drivers are in core's `fuzz_api`
  (feature `fuzzing`, enabled for core's own tests by a self dev-dependency);
  `render_page0` is in `fuzz/src/lib.rs` and repeated in
  `crates/render/tests/fuzz_regressions.rs` (core cannot depend on render):
  change both together. Limits: `fuzz_limits()` (4 MiB file, 32 MiB decoded
  stream, 200k ops and 2 s per page, 200k chars, 4M image pixels) plus a 1,000-page open cap (the text target samples the first 6 pages and the last, so at most 14 s per input)
  and 4M render pixels; libFuzzer runs with `-timeout=20 -rss_limit_mb=2560
  -max_len=4194304`, above every library budget.
- **`cfg(fuzzing)`.** cargo-fuzz passes `--cfg fuzzing` to every crate, path
  dependencies included, which compiles the vendored codec panic boundary
  (patch 0028, H18) out: under fuzzing a codec panic is a crash, not an
  `image: decode failed` warning. cargo-fuzz's default build is release with
  debug assertions and overflow checks, so arithmetic overflow is a finding
  even though a plain release build wraps silently.
- **Running a target by hand** (from the repository root):
  `cargo +nightly-2026-10-01 fuzz build` builds all five;
  `mkdir -p fuzz/corpus/open` then
  `cargo +nightly-2026-10-01 fuzz run open fuzz/corpus/open tests/fixtures/corpus-c -- -timeout=20 -rss_limit_mb=2560 -max_len=4194304 -max_total_time=60`
  fuzzes one (the first directory is the writable corpus and must exist). Findings land in
  `fuzz/artifacts/<target>/`; `cargo +nightly-2026-10-01 fuzz tmin <target> <file>`
  minimises one (never pass `-max_len` to `tmin`: libFuzzer's minimiser
  asserts on it). `fuzz/{corpus,artifacts,target,coverage}/` are git-ignored.
- **Regression set.** `fuzz/regressions/<target>/` holds the minimised input of
  every fixed finding, named by the first 16 hex digits of its SHA-256 and
  committed with the fix. `crates/core/tests/fuzz_regressions.rs` (`open`,
  `text`, `cmap`, `unicode`) and `crates/render/tests/fuzz_regressions.rs`
  (`render`) replay every file through the same driver and limits on a
  measured 512 KiB stack in the ordinary `cargo test --workspace` (CI `rust`
  job); `cargo test -p pdf-extract-core --test fuzz_regressions` runs one.
  Both fail if `fuzz/regressions/README.md` is missing, so a moved set cannot
  pass vacuously. A panic hook counts every panic on the replay thread, so a
  panic the library catches itself (the codec boundary is compiled in here)
  still fails the replay. The dev profile keeps overflow checks, so an overflow-only
  finding reproduces there.
- **Local sessions: `tools/fuzz/run.sh [--minutes N] [TARGET...]`** (default:
  all five, 60 minutes each, in sequence; macOS or Linux; needs the pinned
  nightly and `cargo install cargo-fuzz`). Per target it merges the seeds into
  the persistent `fuzz/corpus/<target>/` (corpus B and C for the document
  targets; `seed-cmaps.py` plus `synthetic_cmaps` for `cmap` (hand-written text CMaps, each checked to parse; they replaced the embedded CMaps, which are `bcmap` data the target drops since H24);
  `fuzz/seeds/unicode/`; and the target's regression set), fuzzes with the
  flags above, runs `cargo fuzz cmin`, replays the document targets' corpus on
  512 KiB threads through all three document drivers (`replay_small_stack all`, a plain release build with
  `--cfg fuzzing` into `fuzz/target/tools/`, no overflow checks), and records
  the session in the ledger. Only the fuzzing is timed, by wall clock. A new
  artifact (crash, timeout, oom or leak; libFuzzer's slow-unit reports are not findings, since 7 sampled pages at the 2 s budget may take 14 s) or a replay that panics or
  dies of a signal is a finding: inputs and `tmin` output are kept
  in `fuzz/artifacts/<target>/` (a replay failure's log too), the target is
  reset, the session stops, exit 1. A cargo failure with no artifact records
  nothing (exit 2), and so does a replay that cannot run. Ctrl-C credits the
  time fuzzed so far, keeps the corpus and skips `cmin` and the replay (the
  next session replays the same corpus); a signal sent to the script alone,
  not its process group, waits for the fuzzer to finish.
- **Ledger policy (`fuzz/ledger.json`, `tools/fuzz/ledger.py`).** Per target:
  `clean_seconds`, `sessions`, `last_reset`, `last_session` and the `HEAD`
  `commit` the hours were earned on. A clean session adds the time fuzzed; a
  finding resets the target to zero; unrelated commits do not. When a fix
  changes a target's code path, the reviewer may reset it by hand with
  `python3 tools/fuzz/ledger.py reset <target>`. The developer commits ledger
  updates in an ordinary PR; it is a progress log, not an attestation.
  `python3 tools/fuzz/ledger.py status` prints every target and "Fuzzing
  depth goal: met/not met"; the goal is met when every target has at least
  72 clean hours. It is **not** a Phase 3 exit or a release gate (ADR 0093):
  callers on untrusted input contain crashes and hangs instead (design spec
  §8.5), and a one-off cloud campaign is optional (internal #167). The scripts run
  on the system `python3` (3.9 on macOS), so they avoid 3.10+ syntax at run
  time; their tests are
  `tests/python/test_fuzz_ledger.py` (run.sh is driven against a stub `cargo`).

## Hardening workflow and sanitizers (ADR 0087)

`.github/workflows/hardening.yml` is **`workflow_dispatch` only** — never add `schedule` or `push`: the repository is billed, long fuzzing is local (`tools/fuzz/run.sh`, `fuzz/ledger.json`), and `ci.yml` depends on nothing here. Dispatch with `gh workflow run hardening.yml --ref <branch> -f job=fuzz-smoke|asan|tsan|all -f fuzz_minutes=10`.

| Job | What |
|---|---|
| `fuzz-smoke` | matrix over `open`, `text`, `render`, `cmap`, `unicode`: `cargo +nightly-2026-10-01 fuzz run` for `fuzz_minutes` (1–60) with the D6 flags, from the seeds (corpus B and C, or `fuzz/seeds/<target>`) plus `fuzz/regressions/<target>`; no cache, no ledger; uploads `fuzz/artifacts/<target>/` on a finding |
| `asan`, `tsan` | `tools/sanitizers/run.sh asan` / `tsan` on ubuntu-24.04, 120-minute timeout; uploads the run log on failure |

`tools/sanitizers/run.sh asan|tsan [cargo test args]` is the same run locally (macOS or Linux):
- `cargo +nightly-2026-10-01 test -Zbuild-std --target <host> --workspace --exclude pdf-extract-python --tests`, `RUSTFLAGS=-Zsanitizer=…`, `CARGO_TARGET_DIR=target/sanitizer-<name>`, output tee'd to `target/sanitizers/<name>.log` (`PXE_SANITIZER_LOG_DIR` overrides). Install the nightly with `rust-src`. The first run builds std, the workspace and Tesseract instrumented: slow.
- `CFLAGS`/`CXXFLAGS=-fsanitize=…` instrument Leptonica, Tesseract and the shim (cmake/cc forward them; `tesseract-sys/build.rs` emits `rerun-if-env-changed` for them and cc's target-scoped variants, because the cmake crate's internal `cc::Build` has `cargo_metadata(false)` and tells cargo nothing). Linux uses clang (gcc's sanitizer runtime is not rustc's). macOS ASan passes `-mllvm -asan-guard-against-version-mismatch=0`: Apple clang references `__asan_version_mismatch_check_apple_clang_*`, which rustc's runtime lacks.
- LeakSanitizer only on Linux (`detect_leaks=1`, `lsan.supp`); TSan uses `tsan.supp` with `halt_on_error=1`.
- `PXE_SANITIZER` is set: the small-stack runner (`crates/core/tests/common/stack.rs`, which core's unit tests include too, ADR 0089) then runs the body on a 64 MiB stack without measuring; the four `stack_size.rs` tests, the unit test `the_unit_tests_small_stack_is_measured`, one wall-clock test, the OCR helper's descriptor-count test and the hanging-helper deadline test are skipped by name, plus two deadline/wall-clock tests and the memory-heavy `runtime_sizes_open_in_hayro` under TSan only (list and reasons in run.sh). On Linux ASan, the five pool unit tests that pretend a fork (`LEAK_BY_DESIGN`: the pool leaks abandoned instances on purpose) run in a second pass with leak detection off, since a suppression would have to name our own crate. On Linux the scripts put Ubuntu's versioned `llvm-symbolizer` on `PATH` so reports are symbolised. `RUST_BACKTRACE` stays unset (per-panic symbolisation slows instrumented panics enough to break `a_failing_worker_stops_the_others`). Doctests, the Python crate and `system-tesseract` are not run.
- Suppressions: `tools/sanitizers/{lsan,tsan}.supp`, each entry under its own `# why:`; entries naming `pdf_extract`, `tesseract_sys` or `pxt_`, or bare wildcards, are rejected by `check-suppressions.sh`, which run.sh calls before building. Findings in our code are issues, never suppressions.
- The nightly is pinned in three places (run.sh `NIGHTLY`, hardening.yml `env.NIGHTLY`, `fuzz/rust-toolchain.toml`); bump them together.

## Wheels and SBOM (ADR 0091)

`tools/build/build-wheel.sh [--out DIR] [--docker x86_64|aarch64] abi3|ft` builds one wheel (default `--out target/wheels`):
- `abi3`: `--features abi3` (`pyo3/abi3-py313`), CPython 3.13, tag `cp313-abi3`; `ft`: no abi3 (free-threaded CPython has no stable ABI), CPython 3.14t, tag `cp314-cp314t`.
- Order: stage the helper (release, default `vendored`), run `tools/license/sbom.py` into `<target>/sbom-<abi>/`, then `maturin build --release --locked --sbom-include …` with maturin at `uv.lock`'s pin in its own venv (`<target>/wheel-tools/`).
- Linux runs only inside `quay.io/pypa/manylinux_2_28_{x86_64,aarch64}` (digests pinned in the script); `--docker` mounts the checkout at `/io`, installs rustup + the pinned toolchain into the mounted cache, and saves/restores the host's staged helper around the run. macOS runs natively with `MACOSX_DEPLOYMENT_TARGET=11.0`.

`tools/license/sbom.py` writes `rust.cdx.json` (the `cargo tree -e normal,no-proc-macro --target <triple>` crates of `pdf-extract-python` and `pdf-extract-ocr`, licences clarified by `about.toml`, vendored hayro crates with a `pedigree` of their crates.io ancestor and the patches touching them, then the pinned toolchain's statically linked standard library from `rust_std.py` as its own group: property `pdf-extract:origin` = `rust-toolchain-<ver>`, crates.io ones with a `pkg:cargo` purl and a `?origin=rust-std` bom-ref (std's hashbrown 0.17.1 is also in `Cargo.lock`), in-tree ones `pkg:github/rust-lang/rust@<ver>#library/<dir>`) and `native.cdx.json` (Tesseract and Leptonica from `vendor/PROVENANCE.md`, the helper with its SHA-256). Standard library only (it runs in the manylinux image); no absolute paths. Its checks (`rust_problems` for the lockfile group, `std_problems` for the std group, `native_problems`, `absolute_path_problems`) are shared with the verifier, which also fails a wheel whose `THIRD_PARTY_NOTICES` does not name some non-`pdf-extract-*` crate of its Rust SBOM as a Part 1 `Used by:` entry or a Part 5 row (`notices_problems`; text elsewhere, such as a licence quoting a crate name, does not count: Part 1 comes from crates/python's graph, the SBOM from each target's extension plus helper, so this catches them drifting apart).

`tools/build/verify_wheel.py --platform linux-x86_64|linux-aarch64|macos-arm64 --abi abi3|ft WHEEL` (dev env; needs cargo for a fresh `cargo tree`): filename tags; one extension, no grafted libs; helper present, 0755, and portable (ELF: `DT_NEEDED` and symbol versions within auditwheel's manylinux_2_28 policy, GLIBC 2.28 / GLIBCXX 3.4.24 / CXXABI 1.3.11 / GCC 7.0.0, which maturin never checks for an included file; Mach-O: thin arm64, minimum OS within the tag, system libraries only); licence files byte-equal; SBOMs valid CycloneDX 1.5 and in agreement. `tools/build/smoke.py [--expect-isolation …] [--gil-off-check]` runs in the installed environment, imports nothing from the checkout, and refuses to test the development tree (`python/pdf_extract`).

**Release workflow** (`.github/workflows/wheels.yml`, ADR 0091): only on `v*` tags and `workflow_dispatch` (never schedule or branch push; billed minutes). Jobs: `version` (`tools/build/release-version.sh`: `docs/releases/v<workspace version>.md` must exist and not be blank, on dispatch too; on a tag, the tag must be `v<workspace version>`; `release` passes that file to `gh release create --notes-file`), `license` (the reusable `license.yml`, ci.yml's `deny` checks on this exact commit; `files`, hence `release`, needs it, so stale notices or a disallowed licence cannot ship), `sdist` (must carry `vendor/`, the build scripts, `tools/license/{sbom,rust_std}.py`, `rust-toolchain.toml`, `uv.lock`, `about.toml`, and no staged helper; pyproject's sdist `include` list), `build` ({linux x86_64 on `ubuntu-24.04`, linux aarch64 on `ubuntu-24.04-arm`, macOS arm64 on `macos-14`} × {abi3, ft}: build, verify, smoke; ft smoke with `PYTHON_GIL=0 --gil-off-check`), `sdist-wheel` (a wheel from the unpacked sdist alone, verified and smoke-tested), `prod-image` (`prod-image-test.sh --image {24.04,26.04}` per Linux arch: 24.04 with a uv-managed CPython 3.13, the Phase 3 exit; 26.04 with apt's `python3`/`python3-venv` 3.14 and pip, the first consumer's platform; only abi3 wheels are accepted), `files` (needs `license` and every build; counts six wheels and one sdist, writes `SHA256SUMS`, uploads them as one `release-files` artifact, on dispatch too), and `release` (tag *push* only, so a dispatch on a tag ref never releases: `gh release create --verify-tag`). The abi3 wheels are smoke-tested on CPython 3.13 and 3.14. maturin's sdist stores every file 0644, so the build scripts run through `bash`, never by their execute bit. Pins: the two manylinux digests (build-wheel.sh), the two Ubuntu index digests, uv 0.12.3 and CPython 3.13.15 (prod-image-test.sh; uv must know the CPython patch release). Landmine: on Docker Desktop, mount the wheel from a shared path (the repository works; `/private/tmp` does not), or the container sees an empty directory.

To try a wheel locally: `tools/build/build-wheel.sh abi3` (macOS) or `--docker aarch64 abi3` (Docker on an arm64 host), then `uv run --no-sync python tools/build/verify_wheel.py …` and `smoke.py` from a fresh `uv venv` outside the checkout.
